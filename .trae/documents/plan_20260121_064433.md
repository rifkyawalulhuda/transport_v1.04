Masalah ini disebabkan oleh cara aplikasi memproses format tanggal dari server.

**Analisis Masalah:**
1.  Server (MySQL) menyimpan tanggal `2026-01-23`.
2.  Saat dikirim ke frontend, formatnya diubah menjadi UTC ISO String, misalnya: `2026-01-22T17:00:00.000Z` (karena perbedaan zona waktu Indonesia GMT+7).
3.  Di file `SalesCostForm.vue`, fungsi `normalizeDate` hanya mengambil bagian depan tanggalnya saja (`.split('T')[0]`), sehingga yang terambil adalah `2026-01-22` (tanggal UTC), bukan tanggal lokal `2026-01-23`.

**Solusi:**
Saya akan memperbaiki fungsi `normalizeDate` di `SalesCostForm.vue` agar mengonversi string tanggal tersebut kembali ke waktu lokal pengguna sebelum mengambil tanggalnya.

**Rencana Perubahan:**
Mengubah logika `normalizeDate` dari sekadar pemotongan string menjadi konversi `Date` objek yang memperhatikan zona waktu lokal.
